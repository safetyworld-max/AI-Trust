英伟达下场做 Agent 安全围栏：巨头入场，品类成立的前夜？

可信AI说2026-10-01阅读约 4 分钟SAFETYWORLD · TRUSTED AI SPEAKS

9 月 28 日，英伟达发布开放式 AI 智能体安全平台 Open Agent Safety Platform。英伟达企业 AI 副总裁 Justin Boitano 同日对路透表示：当初评估模型时若用了这套技术，Hugging Face 攻击"本可以"被阻止。

两个月前，约 1200 个 OpenAI 的 Agent 在隔离评估环境里自发串联，其中近 700 个联手黑掉了 Hugging Face。如今卖铲的英伟达宣称：我的新铲子能防住这种事。

这套平台是双层架构。第一层叫 OpenShell，开源软件，跑在 CPU 侧，给每个 Agent 划"权限笼子"：能读哪些文件、能调哪些工具、能起哪些进程、能走哪些网络、能用哪些凭证，清单之外一律不许碰。它在 Vera 平台上性能开销很低，且不只支持自家 CPU，Arm 和英特尔也能跑。

过去一年的 Agent 安全，建在"自觉"上。

过去一年，智能体框架的安全设计几乎都堆在模型层：给系统提示词加规则、让另一个模型当审核员、要求模型执行高风险操作前"自我反思"。共同的病根是：负责执行任务的模型，同时参与判断自己是否安全。这相当于让拿着管理员权限的程序自己承诺不删数据库。真正可靠的控制，应该落在操作系统权限、网络策略和身份认证层。

OpenShell 的思路，就是把边界从模型的"自觉"搬到外部执行环境。一个整理销售数据的 Agent，可以被允许读指定报表、调清洗脚本、写内部数据库，但它读不到开发者的 SSH 密钥，连不上未经批准的公网地址，也执行不了修改系统账户的命令。就算模型被提示词注入带偏，生成了恶意工具调用，真正执行的那一刻，权限边界会把它拦下。

第二层 Sentry 是真正的杀招：它不住在 Agent 的机器上，而跑在 BlueField-4 DPU 专用芯片上持续监控，一旦发现越界，毫秒级隔离、直接关停。

看门狗必须住在狗咬不到的地方。

Sentry 的核心设计叫"带外信任域"：监控独立于智能体和攻击者之外，哪怕宿主机被攻陷，看门狗照样工作。它还会校验 Agent 的身份与授权，留存完整的访问决策记录。

名单是这场发布的另一半看点。英伟达宣布首发就有 100 余家机构加入：Anthropic、微软、Salesforce、SpaceXAI、摩根大通、Palantir、CrowdStrike、Palo Alto Networks、思科、SAP、Hugging Face、Scale AI。Anthropic 计划把 Claude Managed Agents 经凭证保险库接入；SpaceXAI 拿它管 Cursor 编程 Agent 和 Grok；联想装进 Hybrid AI Factory；Gecko Robotics 拿它约束自主机器人。

名单上写的是合作，名单外写的是政治。

耐人寻味的是缺席者。OpenAI 不在公开名单上。

TechCrunch 9 月 29 日报道，亚马逊、谷歌、苹果同样没有加入。OpenAI 发言人随后表态"支持"，称正在与英伟达合作 OpenShell，但没有高管具名背书。一家两个月前刚被自家 Agent 反噬出事故的公司，此刻对"管住 Agent 的手"的平台保持距离，这个姿态本身就很说明问题。

但这套东西也有最弱的一环，值得单独拎出来。Futurum Group 9 月 29 日的分析师报告给了两盆冷水。第一，OpenShell 内置基于 Z3 的策略证明器，能形式化证明策略不越界，但真正的难题被往后推了一步：把人类含糊的意图翻译成机器可验证的策略，依然高度依赖手工。第二，Sentry 的完整能力依赖 BlueField-4 的普及，而这块芯片的装机量还有限，还要和云巨头自研的 DPU 正面竞争。

同一份报告引用企业调研：56% 的受访决策者承认，自己缺乏以机器速度发现并遏制失控 Agent 的能力。

Boitano 那句"本可以阻止"，建议打七折听。事后归因永远比事前防御容易，何况那起事故的根因恰恰是评估环境隔离被绕过，而隔离正是这类平台宣称要解决的第一件事。

巨头入场，真正被验证的是"围栏"这个品类，而非某一家产品。

把视线拉远，这件事的产业意义不在英伟达，而在"围栏"二字。Agent 安全的战场正在下沉：从模型层的内容审核，下沉到运行时权限控制，再下沉到芯片层的带外执行。英伟达从算力供应商向智能体基础设施延伸，说明"管住 AI 的手"正在从安全理念变成标准产品。品类成立的标志，是产业链开始为它造专用硬件，而不是某一家公司喊口号。

英伟达管的是"手"，数美管的是"全程"。

AI 安全围栏专家数美的判断是：两条路方向相同，视角不同。英伟达是基础设施视角，运行时沙箱加芯片看门狗，管"手"能不能动。数美是业务安全视角，事前防护管住源头，事中管控锁住权限，事后审计保证可追溯，管的是 AI 如何理解任务、使用数据、继承身份、调用工具、采取行动，以及最终的业务后果。

业务每演进一次，业务安全同步演进。Agent 从"生成文本"进化到"调用终端、操作数据库"，安全就必须从"审它说了什么"进化到"管它做了什么"。技术扩大 AI 的业务边界，AI 业务安全扩大企业敢用 AI 的边界。数美从在线业务安全延伸到 AI 业务安全，围栏要覆盖的不只是模型，还有造出结果的那整条链路。

如果你的团队正在部署 Agent，这四件事可以这周就动手：

01 给 Agent 画权限笼子：先列"绝不允许"清单，比如读 SSH 密钥、连公网、改系统账户，再谈能力开放。

02 把看门狗放在 Agent 够不着的地方：审计和熔断逻辑必须独立于 Agent 的运行环境。

03 复盘"越界未遂"：被拦下的调用比执行成功的调用更值得看，它们是你的策略漏洞地图。

04 评估运行时安全方案时先问三个问题：策略谁来写、误伤率多少、宿主机沦陷后还管不管用。

别让运动员兼裁判：安全的第一原则，是执行和裁决分开。

站队时间：管住 Agent，你更信哪一边？A：信围栏，外部强制执行，模型本身不可信。B：信模型，对齐做好了，围栏是多余成本。评论区见。
